## 부록 — 페이지 파일 확대(C-11)가 왜 필요한가

**지금 상태**: 페이지 파일 C:\ 4.6GB(자동 증가 최대 약 8GB). 32K 서버를 띄우면 엔진 private 메모리가 약 35GB 라 물리 RAM 32GB 를 넘고,
가용 RAM 이 약 0.7GB 까지 내려간다(T-003 · Q9). 지금은 엔진이 모델 파일을 메모리 매핑으로 읽어 버틴다.

**Q1(맞춤 양자화)에서 문제가 되는 이유**: 레이어별 양자화는 원본 고정밀 가중치(BF16 약 70GB)를 읽어 다시 양자화하거나, 중요도 행렬(imatrix)을
만들려고 모델을 통째로 돌린다. 도구가 텐서를 한 번에 메모리로 올리면 '커밋 메모리'(RAM + 페이지 파일)가 모자라 변환이 중간에
`out of memory` 로 죽는다. 매핑만 하는 도구라도 Windows 는 커밋 한도를 넘는 할당을 거부한다.

**권장**: Q1 시작 전에 C:\ 페이지 파일을 **고정 64GB**(초기 = 최대 65536MB)로. SSD 여유 1.5TB 라 공간은 충분하다.
변환이 끝나면 원래(시스템 관리)로 되돌린다 — 평소에는 SSD 쓰기만 늘리고 측정에는 이득이 없다.

**방법 (사람이 한다 — 시스템 설정, 재부팅 필요)**: 시스템 → 정보 → 고급 시스템 설정 → 성능 '설정' → 고급 → 가상 메모리 '변경' →
'모든 드라이브에 대한 페이징 파일 크기 자동 관리' 해제 → C: '사용자 지정 크기' 처음 65536 · 최대 65536 → 설정 → 확인 → 재부팅.

**측정에 주는 영향**: 페이지 파일 크기 자체는 추론 속도를 바꾸지 않는다(실제로 페이징이 일어나면 느려진다). 크기를 바꾼 뒤의 측정은
`env/` 에 기록하고, B 단계 수치와 섞어 비교하지 않는다.
