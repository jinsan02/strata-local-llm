# 하드룰 — 이 저장소의 단일 진실 공급원

> **규칙은 이 파일에만 적는다.** `CLAUDE.md`, `AGENTS.md`, `README.md` 는 이 문서를
> 가리키기만 한다. 규칙을 바꾸려면 여기를 고치고 `docs(docs):` 로 커밋한다.
> 다른 파일에 규칙을 복사하면 두 문서가 갈라지고, 갈라진 규칙은 규칙이 아니다.

원본 실험 설계는 [`plan-v2.0.md`](plan-v2.0.md) (기획서), 컨텍스트 목표 변경은
[`plan-v2.1-amendment-20261118.md`](plan-v2.1-amendment-20261118.md). 아래 항목은 기획서의 원칙을
**집행 가능한 형태**로 옮긴 것이다. 각 항목에 "무엇이 이것을 강제하는가"를 붙였다.
강제 장치가 없는 규칙은 지켜지지 않는다.

---

## 1. 엔진은 Niko1221/Strata 의 고정 커밋 하나다

동명의 다른 엔진·포크와 결과를 섞지 않는다. 다른 엔진으로 자동 대체하지 않는다.
업스트림을 올리면 새 기준선으로 따로 비교한다 (기획서 3.1, 12절).

**강제:** 원장 `engine_commit` 열. 같은 비교 묶음에서 값이 다르면 비교하지 않는다.

## 2. 최종 평가 50문항은 후보를 고정하기 전까지 열지 않는다

정답·채점기·문항별 결과는 이 저장소 밖에 둔다. 후보를 고정한 뒤 한 번 연다.
연 뒤에 추가 튜닝했다면 그 세트는 더 이상 독립 평가가 아니다 (기획서 8.1).

**강제:** `.gitignore` 의 `final_eval/`, `pre-commit` 이 경로에 `final_eval` 이 든 파일을
모두 거부. 연 시점은 태그 `final-eval-opened`.

## 3. 측정 기준을 바꿔서 수치를 올리지 않는다

에이전트가 바꿀 수 있는 것은 후보 모델·엔진·실행 설정뿐이다. 평가 정답, 측정 시계,
채점 기준, 원시 결과, 비교 기준선은 고치지 않는다. 평가 도구에 결함이 있으면 고친 버전을
기록하고 **기준선과 후보를 모두 다시 잰다** (기획서 5.1).

**강제:** `fix` 커밋의 `Invalidates`, 태그 `eval-freeze-v1`.

## 4. `record` 커밋과 코드 커밋을 섞지 않는다

**강제:** `commit-msg` 훅 — `record` 커밋에 `experiments/` `reports/` `docs/` 밖의 파일이
있으면 거부. 자세한 것은 [`COMMIT_CONVENTION.md`](COMMIT_CONVENTION.md).

## 5. 원장은 append-only 이고 코드가 쓴다

- 측정 결과는 **전부 TSV 원장**에 들어간다. 마크다운 실험일지를 손으로 쓰지 않는다
- 이미 쓴 행은 고치지 않는다. 정정도 새 행이다
- **실패한 run 도 기록한다** (`status=fail`). 실패 기록이 없으면 같은 실패를 반복한다
- 해시를 손으로 적지 않는다. 원장에서 읽어온다

**강제:** `tools/validate_ledger.py` (pre-commit · CI), `Config-SHA256` 원장 대조.

## 6. 같은 PC 에서 기준선과 후보를 번갈아 잰다

- 측정 전에 `scripts/cleanup.ps1` 을 돌리고, 전원 구성표를 고성능으로 둔다
- 워밍업 후 잰다. cold/warm 캐시를 구분한다
- 탐색은 설정당 3회 이상, 최종 후보는 기준선/후보 교차 쌍 5회 이상
- 중앙값·표준편차·반복 수를 보고한다. 기준선 자체 변동폭보다 작은 이득은 "개선 미확인"
- tok/s 는 엔진이 보고한 토큰 수로만 계산한다. SSE 조각·문자 수로 계산하지 않는다

**강제:** 원장 `settings_id` · `note` 에 반복 수와 캐시 상태를 남긴다.

## 7. 컨텍스트 목표는 실측으로만 달성한다

운영 목표는 **32,768토큰**(입력 최대 24,576 · 출력+reasoning 최대 8,192), 단일 사용자·동시 요청
1개(`--parallel 1`)다. 8K 는 기준선, 16K 는 중간 검증, 64K 는 32K 통과 뒤 선택 탐색이다
([`plan-v2.1-amendment-20261118.md`](plan-v2.1-amendment-20261118.md)).

- 32K 에서 돈다·쾌적하다고 미리 가정하지 않는다. 못 채우면 실패 원인과 16K 운영안을 내고, 달성으로 적지 않는다
- 모델 학습 범위(262,144)를 넘는 RoPE 확장을 임의로 쓰지 않는다
- **컨텍스트 설정 효과**(같은 입력, `--context` 만 다름)와 **입력 길이 효과**(같은 설정, 입력만 다름)를 섞어 해석하지 않는다
- 서버 `--context` 와 클라이언트의 입력·출력 한도·요약 기준은 같은 커밋에서 맞춘다
- 본체 로컬 API 측정과 노트북 경유(네트워크 포함) 측정은 다른 행이다
- 배포 기본값(`--parallel 2`)은 별도 행이다

**강제:** 원장 `ctx` · `input_tokens` · `parallel` · `origin` 열.

## 8. 원본은 덮어쓰지 않는다

원본 모델, 수정 없는 엔진, 원시 측정 결과는 덮어쓰지 않는다. 패치는 분리된 브랜치나
체크아웃에서 관리하고, 검증된 후보만 운영 경로에 반영한다 (기획서 11절).

**강제:** `engine/` `data/` 는 git 밖. 모델은 `model` 커밋의 `Model-SHA256`, 엔진은
`Engine-Commit` 으로 계보를 잇는다.

## 9. 모델·바이너리·비밀값은 커밋하지 않는다

GGUF·팩·설치 파일은 해시만 남긴다. API 키·토큰은 어떤 파일에도 쓰지 않는다.

**강제:** `pre-commit` — 5MB 초과, `.gguf` `.bin` `.safetensors` `.pack`, `engine/`
`data/` `downloads/` 거부.

## 10. 훅을 우회하지 않는다

`git commit --no-verify` 를 쓰지 않는다. 훅이 막으면 그 커밋에 문제가 있는 것이다.
훅 자체가 틀렸다면 훅을 고치고 `fix(infra):` 로 커밋한다.

## 11. 탐색 예산을 지킨다

단계별 후보 최대 20개, 5개마다 검토. 같은 접근으로 3회 연속 개선이 없으면 병목을
다시 확인하고 그 접근을 닫는다. 예산 소진은 개선 성공이 아니다 (기획서 5.2).

## 12. 채택 판정은 변경의 종류로 정한다

30회(6과제 x 5회, 같은 seed) 결과로 채택을 정한다. 기준은 측정 **전에** 정하고, 결과를 본 뒤 바꾸지 않는다(3절).

| 종류 | 무엇 | 채택 기준 |
| --- | --- | --- |
| 일반 변경 | 하네스 · 샘플링 · 노력치 · 양자화 · 문맥 등 모델 출력 분포를 바꾸는 것 | 대조 대비 통과 **−1 이내** · 회귀(import_or_syntax · 기존 테스트) 증가 없음 (11-19 사용자 결정) |
| 손실 없는 엔진 변경 | 같은 가중치 · 같은 수식을 계산 순서나 정밀도(fp16 까지)만 바꿔 계산하는 것. 예: 턴 체크포인트(E1), 디코드 어텐션 재배치(E2a), KV fp16(E2b). KV int8 처럼 값을 줄이는 것은 일반 변경 | (1) 수치 검사 통과: 끈 상태는 기준 엔진과 출력이 같고, 켠 상태는 짧은 greedy 비교에서 갈라짐이 반올림 수준 (2) 30회에서 **유의하게 나쁘지 않음**: 짝 부호 검정 양측 p > 0.10, 숨은 테스트 합 ≥ 대조의 95%, import_or_syntax 증가 1 이하 |

- 손실 없는 변경 여러 개는 수치 검사를 각각 통과한 뒤 **묶어서 한 번** 30회로 판정할 수 있다. 속도 기여는 bench 로 따로 잰다.
- 이유: 손실 없는 변경도 몇 토큰째부터 경로가 갈라져 30회 결과가 우연에 흔들린다(E1: 짝 3:7, p≈0.34). −1 규칙은 이 흔들림보다 좁아 속도 개선을 운으로 떨어뜨린다.
- 11-22 사용자 결정. 이 기준으로도 E1(x3e1v3)은 숨은 테스트 합 455 / 510 = 89% 로 미달이라 보류가 그대로다(사후 구제 아님).

**강제:** STATE 결정 기록, 판정 커밋(record)의 본문에 종류와 기준값을 적는다.
