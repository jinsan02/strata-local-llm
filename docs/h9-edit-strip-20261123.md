# H9: 편집 적용 보강 — 줄마다 공백 무시 한 곳 일치 (11-23)

## 왜

- x3h8(20/30)에서 크게 무너진 marker r2(0/11)는 old_string 첫 줄만 2칸 더 들여 쓴 같은 편집을 5번 반복해 파일이 원본 그대로 남았다. H7 lenient 는 블록 전체가 같은 칸수로 밀린 경우와 줄 끝 공백만 받는다.
- 지난 실행 전체의 실패 편집 40번(11-23 재현, `work/stage/h8/replay_edits.py`): **공백만 틀림 19**(근사 2 포함) · 내용 틀림 16 · 기타 3. 공백이 틀린 모양은 거의 '일부 줄만 +2'. 구제되는 편집이 있는 실패 실행은 6건(x3h8 marker r2 · tags r3 · metadata r1, x3t2h tags r1, x3e1v3 tags r1, x3exh metadata r1).
- 내용 틀림(기억으로 글자를 잘못 씀)은 이 규칙으로 못 고친다. 비슷한 원문 보여 주기(H6 `--edit-hint`)는 예전 12회에서 5 대 5 였다.

## 규칙 (`run_x3.py --edit-apply lenient --edit-strip on`, `g3-chain.ps1 -H9`)

lenient 의 단계(정확히 → 여러 곳이면 거절 → 블록 전체 들여쓰기 이동 → 줄 끝 공백 무시) 뒤 **마지막 단계**로만 동작한다. 앞 단계에서 맞던 편집은 그대로다.

| 항목 | 내용 |
|---|---|
| 맞추기 | old_string 의 앞뒤 빈 줄을 빼고, 줄마다 앞뒤 공백을 없앤 비교로 파일에서 **정확히 한 곳**만 맞을 때 |
| 들여쓰기 | 맞은 줄마다 (파일 칸수 − old 칸수)의 최빈값만큼 new_string 을 옮긴다. 동률이면 0 에 가까운 쪽. new 의 줄이 old 의 어떤 줄과 글자 그대로 같으면 그 줄의 차이만큼 옮긴다(첫 줄만 틀린 경우) |
| 거절 | 여러 곳 일치 · 탭 섞임 · 빼야 할 공백 부족 · **원래 파싱되던 파일이 이 단계 결과로 파싱이 깨질 때** |
| 결과 안내 | "(줄마다 앞뒤 공백 차이는 무시하고 파일 들여쓰기에 맞춰 적용했다)" |
