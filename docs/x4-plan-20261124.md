# X4: 실제 클라이언트로 맡겨 보기 — 준비 (11-24)

## 왜

- X3 · Y 는 우리 하네스(run_x3 의 탐색 루프)로 잰 값이다. 실제로 쓸 때는 **Claude Code · Codex 같은 실제 클라이언트**가 STRATA 서버를 부르고, 워커는 클라우드 지휘자가 MCP 로 일을 넘긴다. 시스템 프롬프트 · 도구 형식 · 턴 관리가 다르므로 같은 점수가 나오는지 따로 본다(계획 8단계 '실제 경로').
- 판정 대상: 맡겨도 되는 작업 범위(유형별 통과 · 시간)와 클라이언트 쪽 문제(도구 호출 형식 · 예산 · 오류).

## A 경로 흐름 (`x4-task.ps1 -Set y -Task <과제> -Rep <n>`)

1. 본체에서 `task.json` · `prompt.md` 만 가져온다. `private/` 는 setup_patch 만(버그 심기) 작업 폴더 밖에 받아 적용 즉시 지운다. **숨은 테스트 · 참조 패치 · 돌연변이는 노트북에 오지 않는다.**
2. 작업 사본: 본체가 만든 git bundle(`work/x4/bundles/packaging.bundle` 3.0MB · `flask.bundle` 12.7MB)에서 고정 커밋, setup 을 커밋으로 넣는다(diff 에 안 섞이게). ssh 로 바로 clone 하면 원격 Windows 셸이 경로 따옴표를 깨서 bundle 로 바꿨다.
3. 지시문 = 과제 원문 + 환경 안내('Python 이 없어 테스트를 돌릴 수 없다, 코드를 읽고 Edit · Write 로 고쳐라, 테스트 파일은 고치지 마라').
4. 실행: `claude -p --output-format json --max-turns 40 --bare --setting-sources project --no-session-persistence --permission-mode acceptEdits --allowedTools Read,Edit,Write,Glob,Grep --disallowedTools Bash,WebFetch,WebSearch,Task`. `--bare` 로 개인 설정의 훅 · 자동 메모리 · 플러그인을 빼고, `--strict-mcp-config`(claude-local) 로 MCP 를 뺀다. 창 64K · 출력 8,192(X3 · Y 와 같게, `claude-local.ps1` 기본값을 11-24 에 64K · min(창/4, 8192) 로 바꿈).
5. diff(새 파일 포함) · 클라이언트 기록(시간 · 턴 · usage)을 본체 `work/x4/in/` 로 보내고 `scripts/bench/x4_grade.py` 가 X3 · Y 와 같은 채점기(fresh_copy + setup → git apply → grade)로 본다. 테스트 파일 수정은 버리고 `tests_touched` 로 남긴다. 결과 `work/x4/results.jsonl`.

PowerShell 5.1 함정 세 가지를 피했다: 인자로 넘기면 지시문의 큰따옴표가 깨진다(→ 파일을 stdin 으로), `>` 는 UTF-16 으로 저장한다(→ `git diff --output`), `Out-File utf8` 은 BOM 을 붙인다(→ BOM 없는 UTF8Encoding).
