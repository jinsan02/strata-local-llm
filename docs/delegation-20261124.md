# 위임 기준 — 지휘자가 로컬 워커에 맡길 일 (11-24)

결정(11-24, A안): **쪼개기와 '로컬에 줄지' 판단은 지휘자(클라우드 Claude · Codex)가 하고, 코드는 기계 확인 · 검증 · 되돌리기만 한다.**
라우터 분류기는 만들지 않는다. 이유는 다음과 같다.

- 과제 종류가 12개(X3 6 + Y 6)뿐이라 규칙을 데이터에 맞추면 과적합된다.
- 막연한 요청을 단위로 쪼개는 일은 어차피 LLM이 해야 한다.
- 지휘자 호출은 작업당 짧은 한두 번이고, 비싼 탐색 · 수정 · 테스트 반복은 로컬이 한다.

**F1 최종 평가는 로컬 단독 성능만 잰다.** 라우팅은 F1 이후 실사용 시연으로 보인다(분리 규칙 S2 유지: 지휘자 판단을 위해 F1 문제를 읽지 않는다).

## 2. 지휘자 체크리스트 (맡기기 전에)

| 항목 | 맡긴다 | 맡기지 않는다 (지휘자가 한다) |
|---|---|---|
| 크기 | 파일 1~3개, 수십 줄 | 4개 이상 → 먼저 나눈다 |
| 성격 | 버그 수정, 작은 기능, 이름 · 구조 리팩터 | 설계, 원인 조사, 여러 모듈 리팩터, 운영 작업 |
| 확인 | `test_cmd` 가 있다(기존 테스트나 지휘자가 쓴 테스트) | 자동 확인 수단이 없다 → 맡기면 diff를 직접 다 읽어야 한다 |
| 명세 | 바꿀 함수, 기대 동작, 예외, 경계 조건을 적었다 | "알아서 고쳐줘" 수준 |
| 테스트 작성 | 지휘자가 테스트를 쓰고, 구현만 맡긴다 | 테스트 작성 자체 (0/5) |
| 경계 조건이 많음 | 경계 조건을 목록으로 적고, 그 조건을 테스트로 준다 | 목록 없이 맡기기 (2/5 ~ 3/5) |

권장 흐름: 지휘자가 요청을 티켓으로 쪼갠다 → (필요하면) 테스트를 먼저 쓴다 → `delegate_code_task` → diff 검토 → `git apply`.

## 4. 실사용 시연 (F1 이후)

- 실제 요청 몇 건(5~10)을 지휘자에게 주고, 쪼개기 → 위임 → 결과를 `route.jsonl` 로 집계한다.
