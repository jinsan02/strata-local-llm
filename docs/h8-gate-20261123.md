# H8: 하네스 검사 게이트 + 요구사항 체크 턴 (11-23)

## 왜

- 기준 x3k64h7(64K · high · H7) 21/30 의 실패 9건 중 7건은 지시 항목 누락 · 위반(둘째 요구 미구현, resolve 빠뜨림, dependency_groups 를 extra 로 셈, 상한에 dev0), 2건은 죽은 코드 · 중복 정의였다. 문법 오류는 0건이라 T1 단독은 효과가 없고(T2 도 17/30 기각), 실패의 주원인을 겨냥하는 장치가 필요하다.
- 지난 실행 148건(실패 60)을 정적 검사로 본 결과(11-22 밤): 실패에서만 걸리고 통과 105건에서는 하나도 안 걸리는 신호가 있었다(정의 안 된 이름 · 중복 정의 · 안 쓰는 새 헬퍼 · 지시문 API 이름 없음 · 기존 테스트 실패).

## 구성 (`scripts/bench/h8_gate.py`, `run_x3.py --h8 on`, `g3-chain.ps1 -H8`)

| 부품 | 언제 | 내용 |
|---|---|---|
| ① 편집 검사 | edit_file 마다 | T1(문법 오류면 쓰지 않음) + 편집 전 · 후를 비교해 새로 생긴 정의 안 된 이름(주석 안 이름 제외) · 같은 몸통의 중복 정의(property setter · overload 제외)를 결과에 경고로 붙인다 |
| ② 남은 턴 알림 | 도구 턴이 3번 남았을 때 한 번 | "아직 하지 않은 수정이 있으면 지금 edit_file 로" |
| ③ 끝 검사 | 예산 끝(강제 턴 직전) 또는 일찍 끝냈을 때, 한 번 | 바뀐 파일의 ① 문제, 지시문 백틱 API 이름(점 이름 · `이름(` · 대문자 둘 이상 CamelCase) 중 정의 없는 것(클래스.멤버는 그 클래스 안에서 확인), 새로 만든 모듈 수준 `_함수` 중 자기 몸통 밖에서 안 쓰이는 것, 공개 회귀 테스트(task.json `regress`, 최대 300초) |
| ④ 체크 턴 | ③ 직후 | 검사 결과 + 지시문 원문을 다시 주고, 항목마다 '파일:줄' 로 확인하고 빠진 것을 고치게 한다. **예산 밖에서 도구 턴 최대 2번**(11-23 사용자 결정), 그 뒤 강제 턴 |

- 턴 수: 예산 끝이면 강제 턴이 20번째 → 22번째(도구 턴 +2). 일찍 끝냈으면 체크 턴 + 도구 턴 최대 2 + (필요하면) 강제 턴. xhigh(호출 30)가 20/30 으로 효과가 없었으므로 '턴이 늘어서' 생기는 효과는 작다고 본다.
- 숨은 테스트 · 참조 패치는 쓰지 않는다(지시문 · 작업 복사본 · 공개 테스트만). 숨은 테스트는 채점 때만 작업 복사본에 들어간다.
- 판정: 일반 변경(RULES 12절) — 30회에서 대조 21 대비 −1 이내 · 회귀 증가 없음. 기대는 22 이상.
