# H7 — 편집 적용을 너그럽게 (11-21, STATE 25-3)

목표: 모델은 그대로 두고, 맞게 고쳤는데 적용 단계에서 버려지는 편집을 살린다. 정확도 손실 없음(모델 입력 · 샘플링 그대로, 바뀌는 것은 적용 규칙과 실패 메시지뿐).

## 1. 실패가 어디서 나는가 (원장 · 답 파일, 서버 없이)

M0 대조 x3s1c(H0 + card-coding, 30회)의 edit_file 도구 호출은 55회 중 1회만 실패했다. 도구 편집 자체는 이미 잘 된다.
실패는 **도구 편집 없이 강제 마지막 턴(도구 없음, 텍스트 편집 블록)까지 간 실행**에 몰려 있다. 주로 metadata_extra_dupes · specifier_bounds 이다.

| x3s1c 30회 | 도구 편집 있음 | 도구 편집 없음 |
|---|---:|---:|
| pass | 14 | 2 |
| test_fail | 6 | 2 |
| no_edit | 0 | 4 |
| apply_fail · import_or_syntax | 0 | 2 |

강제 마지막 턴 답이 버려진 원인은 세 가지였다.

1. **블록 전체를 2~3칸 더 들여 씀**: 기존 dedent 보정은 공통 들여쓰기를 *전부* 빼서 4칸 들여쓰기 메서드를 맞추지 못한다. 예: x3s1c specifier_bounds r4 는 10칸으로 썼고 파일은 8칸이었다.
2. **도구가 없는 턴에 edit_file 을 텍스트로 호출**: `<function=edit_file><parameter=old_string>…`. 서버가 '선언 안 된 도구'로 거절해서 답이 비거나 텍스트로 남는다.
3. **빈 답**: 생각만 하고 끝남. 적용 규칙으로는 못 살린다.

## 2. H7 규칙 (`run_x3.py --edit-apply lenient`, H0 = strict)

강제 턴 편집 블록과 edit_file 도구 양쪽에 같은 규칙을 적용한다. 정확히 한 번 맞으면 예전과 똑같이 처리한다.

| 순서 | 규칙 | 안전장치 |
|---|---|---|
| 1 | 정확히 일치 (H0 와 같음) | — |
| 2 | old/SEARCH 와 new/REPLACE 를 함께 ±1~16칸 옮겨 다시 찾음 | 맞는 이동이 딱 한 가지 · 파일에서 한 곳 · 줄 시작에서만. 두 가지 이상이면 거절 |
| 3 | 줄 끝 공백 무시 (줄 단위) | 한 곳만 맞을 때 |
| 4 | 마지막 답에 편집 블록이 없으면 텍스트 edit_file 호출(path · old_string · new_string)을 편집으로 받음 | old_string 이 비면(새 파일) 받지 않음 |
| 5 | 여러 곳이 맞으면 줄 번호(최대 10개)를 알려 주고 앞뒤 줄을 더 달라고 함 | 적용 안 함 |

edit_file 을 2 · 3번 규칙으로 맞추면 도구 결과에 그 사실을 알린다. 예: "old_string 전체를 -2칸 옮겨야 맞았다". 도구 기록에는 `how` 와 old_string 원문을 남겨, 다음 분석에서는 실패 원인을 바로 볼 수 있게 한다.
`scripts/bench/selftest_edit_apply.py` 로 11개 항목을 점검한다(strict 가 예전과 같음, 각 규칙, 거절 조건).

## 3. 오프라인 재현 (`scripts/bench/replay_edit_apply.py`, 모델 없음)

작업 복사본이 처음 그대로인 실행만 다시 적용할 수 있다(도구 편집이 0인 실행, 마지막 답만 적용). 대상은 9세트(x3s1c · x3rt · x3s1g · x3gr · x3c5h0 · x3g3 M1a · M1b · M1e · M2)이고, 그중 텍스트 답 80건, 빈 답 5건이다.

| | 건수 |
|---|---:|
| 적용 블록이 늘어난 실행 | 15 |
| 그중 숨은 테스트 전부 통과로 바뀜 | 5 (x3c5h0 1 · M1e 1 · M2 3) |
| 바뀌어도 여전히 실패 | 10 |
| 규칙으로 못 살림 (빈 답 · 다른 도구의 텍스트 호출 · 블록 안 들여쓰기가 섞임) | 12 |

- 대조 x3s1c 에서는 통과로 바뀐 것이 없다(specifier_bounds r4 가 0/30 → 27/30). 그래서 M0 에서는 효과가 작을 수 있다. M2 는 11 → 14 가 된다(재현 기준).
- 이 재현은 하한이다. 도구 편집 중 실패가 성공으로 바뀌어 대화가 달라지는 효과는 실측으로만 알 수 있다.

## 4. 측정과 판정

- **측정**: M0 · H7 · H0 와 같은 나머지 설정(card-coding, seed 42~46), 6과제 x 5회, 접두사 `x3h7`. 대조 x3s1c 16/30 은 다시 돌리지 않는다.
  명령은 `g3-chain.ps1 -Only M0 -ForceX3 -Harness H7 -Prefix x3h7 -EditApply lenient -Reps 5` 이다.
- **판정**: 손실 없는 변경이다. 15 이상(−1 이내)이면 해가 없으므로 채택(기본값 lenient)한다. 17 이상이면 효과가 있다고 본다.
  재현 결과로 보면 대조에서 크게 오르기는 어렵다. 실패 유형 중 apply_fail · no_edit 이 줄었는지 같이 본다.
