# X3 전체 기록으로 최적 조합 찾기 (11-21, 사용자 요청)

원장(`experiments/LEDGER.tsv`)의 X3 navigate 행과 실행 폴더 `config.json` 을 이어 붙였다. 6과제 행 653개, 35개 조합이다. SWE 세트(`x3sh*`)와 초기 시험(`x3q` · `x3n`)은 뺐다.
스크립트: `scripts/analysis/x3_combo.py` (numpy 만 씀, 서버의 conda 환경에 scikit-learn · statsmodels 없음).

## 1. 방법

- **요인 효과**: 로지스틱 회귀로 통과(error_type = pass)를 예측한다. 과제마다 절편을 두어 난이도를 보정하고, 요인 계수에는 N(0, 1) 사전분포(ridge)를 둔다. 계수 공분산은 라플라스 근사로 구한다.
- **그리드**: M0 고정, 샘플링 3 x H1 x H7 x C1 x H4 x 64K x 마스킹 x run_tests 의 모든 조합이다(마스킹과 64K 는 같이 두지 않음). 각 조합의 6과제 평균 통과 확률을 사후 표본 600개로 예측하고, 지금 기준(H7 + coding)보다 나을 사후확률을 구한다.
- **외삽 표시**: 그 조합에 들어 있는 요인 쌍 가운데 한 번도 같이 잰 적 없는 쌍의 수.

## 4. 한계

- 지금까지 실험은 한 번에 한 요인씩 바꾼 비교라서 조합 예측은 효과를 더한 외삽이다. 1위 조합(외삽 20쌍)은 예측이 아니라 다음에 잴 순서를 정하는 용도로만 쓴다.
- 같은 설정이라도 세트마다 차이가 크다(card-general H0 대조 9/30 · 13/30 · 19/48). 모델은 실행을 독립으로 보므로 확률이 실제보다 자신 있게 나온다.
- H1 은 짝 비교로는 +2/30 뿐이다(x3c6h1 15 vs x3c5h0 13, 같은 날 card-general). card-coding 과는 같이 잰 적이 없다. specifier 는 H1 에서도 0/5 였다.
- C1 은 짝 비교 48회에서 19 vs 19 였다. 회귀의 +0.45 는 3과제 세트(x3a6r 9/12 vs x3a6b 5/12)에서 온 것이다.

## 5. 다음 순서 (나을 확률이 높고 외삽이 적은 것부터)

2. H1 + H7 + coding (32K): 30회, 약 2시간. 아직 확인하지 않은 가장 큰 후보.
