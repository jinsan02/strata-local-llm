노력치 체인(`effort-chain.ps1`)이 도는 동안 서버 없이 한 일이다. 코드는 측정 중이라 `work/stage/lab_next` 에서 만들고 자체 점검했고, 체인이 끝난 뒤 저장소에 옮겨 커밋한다.

## 1. metadata_extra_dupes 실패 원인 (x3k64h7 5회, 도구 기록 · 원장 note · 숨은 테스트 대조)

과제는 두 가지다: (1) Provides-Extra 중복 검사 (2) Requires-Dist 마커가 선언되지 않은 extra 를 쓰면 오류. 숨은 테스트 20개 중 (1) 관련 · 기존 동작 15개, (2) 관련 5개(`extra ==` · 뒤집힌 순서 · 괄호 안 · `!=` · from_email).

| 회차 | 첫 편집 | 도구 기록 | 마지막 답 | 숨은 |
|---|---|---|---|---|
| r1 | 17번째 호출 | (1)을 edit_file 로 적용 | (2)를 편집 블록 3개로 적용(들여쓰기 2칸 이동, H7 이 맞춤) | 19/20 (`!=` 를 빼먹음: `==` 만 검사) |
| r2 | 없음 | 읽기만 19번 | 블록 4개 중 2개가 SEARCH 불일치 | 15/20 |
| r3 | 없음 | 읽기만 19번(grep `provides_extra` 5번) | (1)만 적용 | 15/20 |
| r4 | 13번째 | (1) 적용, 같은 편집 한 번 더 시도해 실패 | **빈 답**(thinking 상한) | 15/20 |
| r5 | 15번째 | (1) 적용 + 마커 순회 함수 추가 | 텍스트 도구 호출(H7 이 받음)이지만 `from_raw` 연결이 빠짐 | 15/20 |

- **5회 모두 호출 19번에서 강제 마지막 턴**이다(문맥은 최대 35K 로 남음). 처음 13~17번을 읽기에 쓴다: metadata.py 를 처음부터 4~5번 넘겨 읽고(12,000자씩, 잘림 1,700~7,700자), markers.py · _parser.py · requirements.py · errors.py 통째, 같은 grep 반복.
- 그래서 (2)는 늘 강제 턴의 텍스트 블록으로 미뤄지고, 거기서 적용 실패 · 빈 답 · 연결 누락이 난다. **15/20 은 '(1)만 됨'의 점수**다.
- 예상: xhigh(호출 30)는 (2)까지 도구로 할 여유를 준다. → **11-22 결과: 아니었다**(metadata 0/5, 전체 20/30 vs high 21/30). T2(outline · read_symbol)는 읽기 호출 수를 줄인다(실제 metadata.py 개요 1,528자 / 37줄, `Metadata.from_raw` 2,958자 vs read_file 한 번 12,000자).

## 3. T1 편집 직후 문법 검사 (`--syntax-check on`)

- **edit_file**: `.py` 결과가 `ast.parse` 를 통과하지 못하면 파일에 쓰지 않고, 줄 번호 · 메시지 · 편집 후 그 부근 7줄(오류 줄 표시)을 돌려준다. 모델은 다음 턴에 고친다. 새 파일도 같다. H7 들여쓰기 이동으로 맞춘 편집도 검사한다.
- **마지막 답 블록**: 다 적용해 본 뒤 파싱이 안 되는 파일만, 적용 전으로 되돌려 블록을 순서대로 다시 적용하되 파싱을 깨는 블록만 뺀다. 블록 두 개가 같이 있어야 맞는 경우(중간 상태가 깨짐)는 처음에 전부 적용해 보므로 그대로 둔다. 뺀 수는 형식 메모 `syntax_drop<n>`, 오류 유형은 기존 '부분 적용' 규칙을 따른다.
- 손실: 문법이 깨진 파일은 어차피 import 단계에서 모든 테스트가 실패하므로, 빼서 잃는 통과는 없다(깨진 파일이 import 되지 않는 경우만 예외, 이 과제들에는 없음).
- 원장 note `syntax_rejects`(edit_file 거부 수), 출력 JSON 에도 같은 값.

## 4. T2 outline · read_symbol (`--code-tools on`)

- `outline(path)`: 클래스 · 함수 · 메서드(중첩 클래스 포함, 함수 안 함수 제외)의 줄 범위(데코레이터부터) · 인자 이름. 최대 300개.
- `read_symbol(path, name)`: `함수` 또는 `클래스.메서드` 의 전체 소스를 줄 번호와 함께(최대 400줄, 넘으면 이어 읽을 `start_line` 안내). 같은 이름이 여러 곳이면 후보를 보여 주고 고르게, 없으면 비슷한 이름 제안.
- 켜면 도구 목록 · 사용 가능 도구 문장 · 과제 끝 안내 한 줄("큰 파일은 outline 으로 구조를 본 뒤 필요한 부분만")이 바뀐다. 끄면 지금과 같다.

- 지금 워커는 옛 설정(H0 · card-general · strict · 32K)으로 돌고 있었다. 새 설정: **H7(lenient) · card-coding · 서버 64K · 노력치 high**(11-22 노력치 결과로 medium → high, 최대 high). 자동 올리기 코드(retry escalate)는 남기되 기본은 올릴 단계가 없다. syntax_check · code_tools 는 측정으로 채택되면 켠다.
