## 2. 모델의 컨텍스트 지원

- Qwen3.6-35B-A3B `config.json`: `max_position_embeddings = 262144`, `rope_scaling` 없음. 16K·32K·64K 는 **학습 범위 안**이다. RoPE 확장(`--rope-scaling`)은 쓰지 않는다.
- 하이브리드 구조: 40층 중 4층마다 full attention → attention 층 10개 (+ MTP 블록). KV 는 그 층만 쓴다. QWEN36.md 기준 fp32 에서 토큰당 약 45KB, 32K 에서 약 1.5GB. 설정 기본은 `--kv int8`.
- **STRATA 에서 실제로 16K·32K 가 실행되는지는 가정하지 않는다.** 단계별로 로딩·응답·메모리를 실측해서 판정한다 (3절 X0).

## 3. 컨텍스트 단계

| 단계 | 컨텍스트 | 역할 | 넘어가는 조건 |
| --- | --- | --- | --- |
| C8 | 8,192 | 초기 실행·기준선 확인 (B0) | 로딩·로컬 API 응답·OOM 없음 |
| C16 | 16,384 | 중간 검증 | C8 과 같은 조건에서 로딩·응답, 메모리 증가량 확인 |
| **C32** | **32,768** | **실사용 운영 목표** | 4절 예산으로 코딩 세션 품질·속도·메모리·안정성 통과 (6절) |
| C64 | 65,536 | 선택 탐색 | C32 가 통과한 뒤에만 |

## 4. 32K 예산과 클라이언트 맞춤 (초기안)

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 서버 컨텍스트 | 32,768 | `--context 32768` |
| 입력 예산 | 최대 24,576 | 시스템 지침·도구 정의·대화 기록·코드·도구 결과·템플릿 포함 |
| 출력 + reasoning 예산 | 합계 최대 8,192 | `max_tokens` 8,192 |
| 클라이언트 요약 기준 | 입력이 약 20,000 을 넘으면 요약 | 24,576 에 닿기 전에 여유 4.5K |

| 클라이언트 | 설정 |
| --- | --- |
| Claude Code (`scripts/client/claude-local.ps1`) | `CLAUDE_CODE_MAX_CONTEXT_TOKENS=32768`, `CLAUDE_CODE_MAX_OUTPUT_TOKENS=8192`, `CLAUDE_CODE_SIMPLE=1` (프롬프트 15.6K → 1.25K) |
| Codex (`scripts/client/codex-local.ps1`) | `model_context_window=32768`, `model_max_output_tokens=8192`, `model_auto_compact_token_limit=20000` (프롬프트 약 8.6K) |

- STRATA 권장값(`strata connect`)은 출력 4,096 이다. 이 계획의 예산 배분(출력+reasoning 8,192)에 맞춰 올렸다. reasoning 이 예산을 자주 다 쓰면 다시 조정하고 이유를 기록한다.
- 예산을 바꾸면 서버 `--context`, 클라이언트 두 스크립트, 이 표를 같은 커밋에서 고친다.

| 조건 | 고정값 | 근거 |
| --- | --- | --- |

| 그림 | `--vision off` | 코딩 용도 |

| 프롬프트 캐시 | 엔진 기본, cold/warm 을 구분해 기록 | |

## 6. 실험 매트릭스 (기존 B0~F1 에 추가)

### X0. 컨텍스트 지원 확인 (각 단계 1회)
C8 → C16 → C32 순서로 로딩·짧은 요청·`/v1/models`·종료를 확인한다. 실패하면 다음 단계로 가지 않고 원인(OOM, 엔진 거부, 할당 실패)을 원장에 `fail` 로 남긴다.

### X1. 컨텍스트 **설정** 효과 — 입력 길이 고정
| 고정 | 바꾸는 것 |
| --- | --- |
| M0 · E0 · S0 · 같은 고정 문항(입력 512·2,048·4,096, 출력 128·512) | `--context` 8K · 16K · 32K |

할당 메모리(VRAM 에 남는 expert 수, KV·버퍼), PP·TG, 지연 차이를 본다. **서로 다른 입력 길이의 결과를 섞어 설정 효과로 해석하지 않는다.**

> **X1 결과의 이름 (11-18 사용자 지시):** "8K·16K·32K 설정에서 0.5K·2K·4K 입력 성능 측정"이다.
> 짧은 입력의 처리량 시험이며 **32K 실사용 검증이 아니다.** 출력 512 는 전부 reasoning 이라 최종 답변·품질은 판정하지 않았다.

### XB. 출력·reasoning 예산 단계 시험 (11-18 추가) — 설정 32K
출력 제한 512 결과는 처리량 시험으로 보존한다. 별도로 같은 코딩 과제(`configs/eval/explore-coding`, 고정 단위 테스트)를
예산 2K → 4K → 8K 로 보내 **최종 답변 도달 여부(`answer_reached`), 실제 사용 토큰, `finish_reason`, 테스트 통과(`tests_passed`)**를
기록한다. 8K 가 필요하다고 미리 결론 내리지 않는다 — 가장 작은 충분한 예산을 찾는다.

### X2. 실제 **입력 길이** 효과 — 설정 32K 고정
입력(템플릿 포함, 서버 보고 `prompt_tokens`) + 출력·reasoning 예산이 **32,768 을 넘지 않게** 한다. 러너가 넘는 조합을 거부한다.

| 작업 | 실제 입력 (템플릿 포함) | 예산 |
| --- | --- | --- |
| 짧은 코드 질문 | 약 2K | XB 결과 |
| 관련 파일 여러 개 | 약 8K | XB 결과 |
| 도구 호출·테스트 로그가 누적된 세션 | 약 16K | XB 결과 |
| 32K 한도 근처 | 32,768 − 예산 − 여유 256 | XB 결과 |

### 코딩 실사용 성능의 판정 (11-18 사용자 지시)
같은 프롬프트에서 **실제 최종 답변이 나오고 품질(테스트 통과)이 확인된** 행만 코딩 실사용 성능으로 본다.
처리량·지연만 있는 행은 처리량 시험이다. 각 조건에 Peak VRAM·RAM, expert 캐시 상태(`experts_vram`), SSD 의존도(`ssd_read_mb`)를 남긴다.
첫 reasoning 수신(`tt_reasoning_ms`)과 첫 최종 content 수신(`tt_answer_ms`)을 나눠 기록한다.

### X3. 긴 문맥 코딩 품질 (탐색 세트, 최종 50문항과 분리)
지시 준수, 관련 코드 찾기, 수정 정확성, 테스트 통과율, 도구 호출 정확성(형식·인자·순서)을 X2 의 길이별로 본다.

### X4. 노트북 경유 체감 지연과 호환성
본체 로컬 API 측정(X1~X3)이 끝난 뒤, 노트북에서 Tailscale 로 같은 작업을 돌린다. 네트워크를 포함한 체감 지연은 **별도 행**으로 기록하고 본체 측정과 섞지 않는다. Claude Code(Anthropic messages + tools)·Codex(responses + tools)의 tool calling·채팅 템플릿 호환을 확인한다.

### 이후 최적화 (기존 흐름 유지, 조건은 C32)
B1 설정 튜닝(KV `int8/q4_0/k8v4`, expert 캐시·VRAM 예산, prefill 청크, MTP) → Q1 맞춤 양자화 → E1 프로파일 기반 엔진 수정 → C1 결합. 32K 에서 KV·expert 캐시·연산 버퍼가 VRAM 을 두고 경쟁하는지 X1 결과로 먼저 확인하고, 병목에 근거해 조정한다.

- 실행 중 expert 배치 변경(엔진 기능)과 가중치 정밀도 변경(양자화, 재로딩)을 구분한다. 런타임 Q4↔Q8 전환은 기본 지원으로 가정하지 않는다.
- 컨텍스트를 늘리려고 품질을 무조건 낮추지 않는다. 필요한 파일만 읽기, 도구 출력 제한, 대화 요약을 함께 검토한다.
- 효과가 확인되지 않은 패치는 운영 구성에 넣지 않는다.

## 8. 어느 기기에서 무엇이 도는가

| 일 | 기기 |
| --- | --- |
| 모델 추론 (STRATA 서버) | 본체 |
| 코드 읽기·수정·테스트 실행, 도구 호출 실행 | **노트북** (클라이언트가 자기 작업 폴더에서) |
| 모델이 보는 코드 | 클라이언트가 요청에 넣어 보낸 것뿐 |

모델 API 에 접속한다고 본체나 노트북 파일에 자동으로 접근하지 않는다. 본체의 코드를 다루려면 그 코드가 노트북 작업 폴더에 있어야 하고, 본체에서 테스트를 돌리려면 클라이언트가 SSH 같은 별도 경로를 써야 한다.

접속은 Tailscale(사설망)과 API 키로만 한다. 방화벽은 Tailscale 대역(100.64.0.0/10)의 8080 만 연다. 인터넷에 인증 없이 열지 않는다 (`--access cloudflare` 같은 공개 터널은 쓰지 않는다).

## 9. 32K 가 부적합할 때

32K 를 통과로 처리하지 않는다. 실패 원인(메모리·속도·품질·안정성 중 무엇이 기준을 못 넘었는지, 수치)을 보고하고 **16K 운영안**을 낸다.

| 16K 운영안 | 값 |
| --- | --- |
| 서버 | `--context 16384` |
| 입력 / 출력+reasoning | 약 12,288 / 4,096 (같은 비율로 시작) |
| 클라이언트 | Claude Code `CLAUDE_CODE_SIMPLE=1` 필수, Codex 요약 기준 약 10,000 |
